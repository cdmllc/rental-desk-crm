# Rental Desk

不動産賃貸仲介の社内業務をまとめて管理するCRMです。顧客、案件、必要書類、タスク、売上、入金予定を1つの画面で確認できます。

## 主な機能

- ダッシュボードで進行案件、売上、粗利、入金予定、未入金、要対応案件を確認
- 顧客情報と担当者を手動登録
- 賃貸仲介の進行状況に合わせた案件ステータス管理
- 物件、内見、申込、契約、入居日程の管理
- 必要書類チェックリスト、タスク、メモの管理
- 仲介手数料、AD、その他報酬から売上を自動計算し、提携先手数料を原価として粗利を算出
- 人材・ライフライン案件は売上単価と原価単価から売上・粗利を算出
- 案件を事業、進捗区分、ステータスで絞り込み、次回対応期限・売上・粗利で並び替え
- 入金予定日、実入金日、入金済み・未入金の管理
- 管理者・担当者のメールアドレス／パスワード認証
- ログイン画面からの利用申請と、管理者による承認・却下
- 顧客・案件・タスクを担当者IDで分離し、API側でも担当外アクセスを拒否
- Slackへタスク期限を前日09:00、当日12:00、未完了なら当日16:00に通知し、16:00は管理者にも連絡
- 管理者による担当者アカウントの追加、停止、削除、権限変更、初期パスワード再発行
- 通信現場スタッフの稼働ダッシュボードと日報承認・差戻し
- スタッフ、所属会社、雇用区分、通信案件、現場、稼働区分、成績項目の管理
- 通信の案件種類を自由に追加・編集・停止・削除し、売上入力画面から直接管理
- 適用期間付き日給、領収書付き交通費申請、承認済み日報に基づく月次報酬計算・確定スナップショット
- 月次報酬CSV出力、通信案件別の売上・粗利管理、月末締め翌月末入金でCRMダッシュボードへ合算
- CRM権限と稼働・報酬権限の独立管理
- `/staff` のスマホ専用画面から、本人の日報作成・提出・差戻し修正・報酬確認
- 利用申請時にCRM担当者／現場スタッフ／両方を選択し、承認時に権限を自動設定

## 技術構成

- React / Next.js互換構成（Vinext）
- TypeScript
- Cloudflare Workers / D1
- Drizzle ORM

## ローカル起動

Node.js 22.13以降とpnpmを使用します。

```bash
pnpm install
pnpm dev
```

既定では `http://localhost:5173` で起動します。

## ビルド

```bash
pnpm build
```

## データについて

CRMの初回起動時は操作確認用の架空データを表示します。通信稼働・日報にはサンプルスタッフや日報を投入しません。保存したデータはD1に保持されます。

## アクセス

ソースコードは公開しています。稼働中のCRMはアプリ内認証を有効にし、担当者は自分に割り当てられた顧客・案件・タスクだけを取得・更新できます。新しい担当者はログイン画面で自分のパスワードを設定して利用申請し、管理者の承認後にログインできます。管理者が直接発行した初期パスワードは、初回ログイン時に変更が必要です。

「稼働・報酬」は管理者専用モジュールです。CRMデータとは別のD1保存領域を使用し、`CRM権限` と `稼働・報酬権限` をアカウントごとに独立設定できます。同じアカウントに両方の権限を持たせることもできます。現場スタッフは `/staff` に入り、自分の日報と報酬情報だけを取得・更新できます。

## Slackタスク通知

タスクの期限通知は日本時間で次の3回です。完了済みのタスクは対象外になり、同じタスク・期限・通知時刻の組み合わせは送信履歴で重複を防ぎます。

- 期限前日の09:00: 担当者へ通知
- 期限当日の12:00: 担当者へ通知
- 期限当日の16:00: 未完了の場合、担当者へ再通知して管理者にもエスカレーション

本番環境には次の環境変数を設定します。Webhook URLと定時実行キーは秘密情報として扱い、画面・ソースコード・ログには保存しません。

| 設定先 | 変数名 | 必須 | 用途 |
| --- | --- | --- | --- |
| Sites | `SLACK_WEBHOOK_URL` | はい | Slack Incoming Webhook URL |
| Sites | `SLACK_CRON_SECRET` | はい | 定時実行APIの認証キー |
| Sites | `SLACK_CHANNEL` | いいえ | 通知先チャンネル。未設定時はWebhookの既定チャンネル |
| Sites | `SLACK_NOTIFICATIONS_ENABLED` | いいえ | `false`で全送信を停止 |
| Sites | `CRM_BASE_URL` | いいえ | 通知内のCRMリンク。既定は本番URL |
| GitHub Actions secret | `CRM_SLACK_CRON_SECRET` | はい | Sitesの`SLACK_CRON_SECRET`と同じ値 |

担当者管理で各アカウントのSlackメンバーID（`U`または`W`から始まるID）を登録すると、本人をメンションします。管理者もSlackメンバーIDを登録すると16:00のエスカレーションでメンションされます。設定後はタスク画面の「テスト送信」で疎通を確認できます。

Webhookが未設定、または`SLACK_NOTIFICATIONS_ENABLED=false`の場合は外部送信を行いません。GitHub Actions側のsecretが未設定の場合も定時実行をスキップします。
